# Finance

The core domain bucket: the Excel-workbook loop (explore → plan → build → log), Velixo/Acumatica reporting, and the workbook audits.

**The workbook loop is complete end-to-end** — all seven `workbook-*` skills are registered and the loop runs explore → plan → build → log. The loop is **user-invoked** with `workbook-explore` as a present-and-name router; the deep dive is folded into it as an inline **Full-orientation mode** (no separate skill). The shared contracts are reference files — one canonical file per contract, owned by a single skill and reached by every other writer via a **contract pointer**, a prose reference naming the owning skill and the exact in-skill path: `workbook-onboarding/` holds the sheet-shaped canonicals: the Sheet conventions inline in its `SKILL.md`, `AUDIT-LOG-FORMAT.md`, and the opt-in `MULTI-SESSION.md` (the sheet-layer creator owns the specs of the sheets it lays down; `handoff-format` stays with its sole consumer). `workbook-log` is the **WRITER end of the stub lifecycle** and the heaviest contract consumer, reaching the hub's canonicals via contract pointers. The two reference skills (`excel-finance-workbooks`, `velixo-formulas`) are the bucket's only **model-invoked** skills — the legal user→model direction the loop conditionally composes (`workbook-plan`/`-build` load them on signals; `workbook-onboarding` requires `excel-finance-workbooks`; `workbook-explore`'s Full-orientation mode composes `velixo-formulas`) — so the listing groups **User-invoked** and **Model-invoked**. The audits (`formula-audit`, `logic-audit`) are escalation targets, not loop phases; `workbook-handoff` is a peer to the loop, not a phase. The workbook-native grill lives inside the cross-substrate `/grill-with-files` as a **deepened workbook branch** (the Instructions/Agent/Audit-Log layers + a tie-out pressure) — not a separate skill — and the loop is wired into `ask-ef` as its **workbook-native build-arm**. Finance takes **no** `GLOSSARY.md`/`docs/adr/` add-on — the four-sheet model (Instructions ≈ glossary, the Agent sheet's open decisions ≈ decision home, the Audit Log ≈ dated history) is the native equivalent.

## User-invoked

Reachable only when you type them (`disable-model-invocation: true`).

- **[workbook-explore](./workbook-explore/SKILL.md)** — Orient to a workbook at session start: a fast state-check, then an adaptive routing menu (Resume, Quick Pickup, Full orientation, Read-only scan, Onboard). The loop's session-start router, with the deep dive folded in as an inline mode.
- **[workbook-onboarding](./workbook-onboarding/SKILL.md)** — Open a workbook for the first time and make it understandable: read the full structure, lay down an Instructions sheet (humans), an Audit Log (history), and an Agent sheet when there is standing guidance to record, and surface findings. Canonical owner of the sheet conventions (inline in its `SKILL.md`), the Audit Log block format (`AUDIT-LOG-FORMAT.md`), and the opt-in multi-session machinery (`MULTI-SESSION.md`). The first-visit mode.
- **[workbook-pickup](./workbook-pickup/SKILL.md)** — Quick re-orientation for an already-onboarded workbook: read the Instructions sheet + latest Audit Log block, return a locked six-line summary, flag anything in-flight, then stop. The return-visit mode.
- **[workbook-plan](./workbook-plan/SKILL.md)** — Draft a six-section plan (Goal, Approach, Steps, Validation/Tie-outs, Open Questions, Out of Scope) before executing, and write the In-progress stub to the Audit Log. Validation/Tie-outs is the keystone; reaches the block format via contract pointer (`AUDIT-LOG-FORMAT.md`, canonical `workbook-onboarding`). The planning phase.
- **[workbook-build](./workbook-build/SKILL.md)** — Execute a finalized `/workbook-plan` with discipline: per-step reporting, inline Validation/Tie-outs as affected Steps complete, destructive-op confirmation, and a Surfaced list for out-of-scope discoveries. Reads the In-progress stub (never writes it); lightweight mode when there's no plan. The execution phase.
- **[workbook-log](./workbook-log/SKILL.md)** — Close out a task: complete the In-progress stub in place (or append a standalone block), refresh the Workbook Snapshot if the task changed it, clear the Handoff sheet, and propose Agent-sheet updates when the work surfaced standing guidance. Reads `/workbook-build`'s `Status` and determines `Cancelled` itself; reaches `AUDIT-LOG-FORMAT.md` and the `SKILL.md` Sheet conventions (both canonical `workbook-onboarding`) via contract pointers. The close-out phase.

The **handoff peer** is invoked at any point during an active task to pause work for a future session — a peer to the loop, not a phase (a distinct lifecycle from `/workbook-log`: pause-and-resume vs task-complete/cancelled).

- **[workbook-handoff](./workbook-handoff/SKILL.md)** — Write a **Handoff sheet** so a future session resumes a paused task cleanly: task goal, plan, decisions, progress, next action, and the expensive-to-rediscover context. The sole creator of the Handoff sheet that `/workbook-explore` detects and `/workbook-log` clears; owns the `handoff-format` contract (`HANDOFF-FORMAT.md`) and reaches the sheet contract via contract pointer. Points non-workbook work at `/handoff`.

The two **audits** are user-invoked escalation targets, not loop phases — `/workbook-explore`'s Full-orientation mode present-and-names them when its scan warrants a deeper look. Run `/formula-audit` first; it's the mechanical pass.

- **[formula-audit](./formula-audit/SKILL.md)** — Read-only mechanical QA scan of a workbook's formulas: error values, buried hardcodes, broken cross-sheet links, off-by-one ranges, pattern breaks, unit/scale mismatches, and stale live-data (Velixo) formulas, returned as a severity-ranked findings table. Changes nothing unless asked. The mechanical sibling of `/logic-audit` — "are the formulas right?"
- **[logic-audit](./logic-audit/SKILL.md)** — Decode and audit the business logic: the classification scheme that sorts source records into reporting buckets via filters, checked for the five invariants (exhaustive, exclusive, correct, consistent, reconciled). Runs as a lightweight Scan (chat) or a full Decode (a reference sheet, prose-only — defers visual conventions to `/excel-finance-workbooks`). The business-logic sibling of `/formula-audit` — "is the logic right?"

## Model-invoked

Model- or user-reachable (rich trigger phrasing so the loop can compose them and the model can reach for them). The user-invoked loop pulls these in as knowledge — the legal user→model direction.

- **[excel-finance-workbooks](./excel-finance-workbooks/SKILL.md)** — The resilient-architecture knowledge base: source-of-truth design, name-based-over-positional lookups, the Checks sheet, sign conventions, refactoring and finance-model judgment, programmatic-generation caveats, and the resilience checklist. Composed by `/workbook-plan`/`-build` on structural work; required by `/workbook-onboarding`.
- **[velixo-formulas](./velixo-formulas/SKILL.md)** — Reference for the Velixo Reports Excel functions that pull live Acumatica ERP data: the workhorse syntax (ACCOUNTTURNOVER, ACCOUNTSANDSUBACCOUNTSWITHHISTORY, GI) and the performance patterns (array-aware calls, the MAP+LAMBDA anti-pattern, period-format gotchas) that decide whether a workbook refreshes in seconds or minutes. Composed whenever Velixo/Acumatica work is in scope.
